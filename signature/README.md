# Авторская подпись Антона Гороховатского

Общий Web Component `<ag-signature>`. Принятая графика — вариант 07 «Плотное
ядро», 14 октября 2026 года: дуга фавикона, крест, вплетённые узлы карты.
Размер по умолчанию — 128 × 92 CSS px при корневом кегле 16 px. Частицы идут
по прежним траекториям за 12 и 18 секунд; рисунок не вращается целиком.

**Выпуск: 1.0.5, 15 октября 2026 года.**

- Общий канал совместимых обновлений: [v1/signature.js](https://gorokhovatsky.tech/signature/v1/signature.js).
- Зафиксированная версия: [1.0.5/signature.js](https://gorokhovatsky.tech/signature/1.0.5/signature.js).
- [Примеры подключения](https://gorokhovatsky.tech/signature/demo.html) без CSS портфолио.

Компонент можно подключать с других доменов. Страница `/404.html`
использует этот общий компонент с внешним управлением движением сайта.

## Один источник

- `src/mark.svg` — принятый рисунок, без перерисовки при подключении к проектам.
- `src/motion.css` — принятые траектории и фазы прозрачности.
- `src/component.css`, `src/component.js` — изолированная подпись и её поведение.
- `build.mjs` собирает всё в один `v1/signature.js`; дополнительных загрузок нет.

```sh
node signature/build.mjs
```

Редактировать исходники, затем пересобирать. Не править сгенерированный файл
и не переносить SVG из экспериментальных `.qa-artifacts` в каждый проект.

## Подключение

Подключить модуль один раз на странице, затем поставить подпись в нужное место:

```html
<script type="module" src="https://gorokhovatsky.tech/signature/v1/signature.js"></script>

<ag-signature role-label="Дизайн и разработка">
  <a href="https://gorokhovatsky.tech/" rel="author">
    Антон Гороховатский — Дизайн и разработка
  </a>
</ag-signature>
```

Адрес `/v1/` получает совместимые обновления из общего источника. Чтобы
закрепить нынешний выпуск, заменить в адресе `/v1/` на `/1.0.5/`.
Уже открытая страница сохраняет загруженный модуль до перезагрузки;
получение обновления при следующей загрузке зависит от кэша браузера и CDN.

Вложенная ссылка — запасной вариант до загрузки модуля, при отключённом
JavaScript или сетевой ошибке. После загрузки она заменяется представлением
в Shadow DOM, без второй ссылки в доступном дереве. Текст роли и запасной ссылки
нужно согласовать с реальным вкладом в конкретный проект.

В английской версии имя отображается как «Anton Gorokhovatsky». Для отдельного
английского примера на русской странице поставить `lang="en"` на `<ag-signature>`;
вложенная запасная ссылка использует то же имя.

Компонент не загружает шрифт: он наследует шрифт проекта. Не использует React,
хранилище, аналитику или запросы данных. Ссылка остаётся обычным `<a href>`;
декоративный рисунок скрыт от диктора.

## Параметры

| Параметр | Назначение |
| --- | --- |
| `href` | Адрес перехода из подписи. По умолчанию `https://gorokhovatsky.tech/`; для конкретного проекта можно указать полный URL с `?point=…`. |
| `lang="ru"` / `lang="en"` | Язык имени, роли по умолчанию и кнопки движения. Без атрибута наследуется язык страницы. |
| `role-label` | Текст роли. По умолчанию «Дизайн и разработка»; пустая строка скрывает роль. |
| `theme="light"` / `theme="dark"` | Палитра знака. Без атрибута следует системной цветовой схеме. Цвет текста наследуется от сайта. |
| `paused` | Останавливает движение в текущей фазе. Удаление атрибута продолжает его. Есть свойство `element.paused`. |
| `layout="compact"` | Компактная группа в футере: знак слева, имя и роль сверху, пауза под текстом. На узком экране знак стоит над кредитом. |
| `controls="external"` | Убирает встроенную кнопку паузы, когда сайт уже предоставляет видимое управление движением. |

С версии 1.0.4 `href` задаёт адрес обычной ссылки внутри компонента и реагирует
на изменение атрибута. Тот же адрес нужно указать во вложенной запасной ссылке,
чтобы результат перехода сохранялся без JavaScript или при ошибке загрузки.
Без `href` прежние подключения продолжают вести на главную страницу портфолио.

CSS-параметры на самом элементе:

```css
ag-signature {
  --ag-signature-size: 8rem;
  --ag-signature-ink: var(--content-ink);
  --ag-signature-muted: var(--content-muted);
  --ag-signature-accent: var(--signal);
  --ag-signature-node-ink: var(--content-ink);
}
```

Дополнительно доступны `--ag-signature-name-size` (1.25rem),
`--ag-signature-role-size` (.875rem), `--ag-signature-gap` (1rem),
`--ag-signature-practice` (#6e9484), `--ag-signature-personal` (#a098b0).
Последние два цвета относятся к узлам карты; менять их без содержательного
основания не нужно. Ни один CSS-параметр не меняет траектории или форму знака.

С версии 1.0.5 для согласования стрелки с небольшим кеглем доступны
`--ag-signature-arrow-size` (.75rem), `--ag-signature-arrow-gap` (.5em) и
`--ag-signature-arrow-stroke` (.09375rem). Их значения по умолчанию сохраняют
прежний вид. Например: `.65em`, `.25em`, `.08em`.

`layout="compact"` включает отдельную компоновку: знак занимает левую колонку,
а имя, роль и управление движением — правую. До 680 px они выстраиваются
вертикально. Рисунок и траектории остаются прежними; подключения без этого
атрибута сохраняют своё расположение.

С версии 1.0.3 доступны публичные CSS Parts: `credit`, `mark`, `text`, `name`,
`role`, `arrow`, `motion`. Принимающий сайт может согласовать вес, интерлиньяж,
подчёркивание, масштаб стрелки и компоновку подписи через `ag-signature::part(...)`.
Например, `ag-signature::part(name) { font-weight: 400; letter-spacing: normal; }`.
Оформление по умолчанию сохраняется; графические элементы внутри знака
не открыты для отдельных переопределений.

Компонент сохраняет мобильную компоновку: до 680 px знак стоит над именем.
Внешнее расположение и отступы задаёт футер принимающего сайта. После первого
подключения смотреть подпись в его реальной композиции, а не только на демо.

## Движение

По умолчанию есть собственная доступная кнопка «Остановить движение».
На 404 используется существующая общая кнопка сайта и `controls="external"`.
Компонент понимает `html[data-reduce-motion="true"]`. Другой сайт может
вместо этого управлять атрибутом `paused` из своего видимого переключателя.
Не скрывать встроенную кнопку без эквивалентного управления.

`prefers-reduced-motion: reduce` и forced colors оставляют неподвижный рисунок.
В скрытой вкладке, за пределами экрана и при отключении элемента движение
приостанавливается. Повторное подключение не создаёт дополнительные обработчики.
Компонент не пытается обходить системное уменьшение движения.

## Соразмерная проверка и выпуск

Изменения только `signature/` выбирают профиль `signature` в общем каталоге
проверок. Локальный preflight проверяет синтаксис, чистую воспроизводимую сборку,
совпадение `v1` с текущей фиксированной версией и сохранность прежних выпусков.
Он не переписывает исходники и не исправляет сборку во время проверки.

```sh
node scripts/check-project.mjs --scope=signature
node scripts/check-project.mjs --scope=chromium --checks=signature
```

Quality выполняет только этот preflight и два коротких сценария компонента —
Chromium и Linux WebKit: русское и английское имя, обе поверхности примера,
ссылка и фокус, пауза и reduced motion, 320 px, текст 200% и запасная ссылка
без JavaScript. Карта, медиа, WHOOP и другие страницы портфолио не загружаются.
Полный diff между опубликованным `gh-pages` и кандидатом определяет объём:
изменение других исходников сохраняет их прежние проверки, а общие и
неизвестные изменения требуют полного набора. Последний маленький коммит
не скрывает более раннюю неопубликованную правку.

`release.mjs` использует тот же профиль и проверяет на публичном адресе
модуль `v1`, фиксированную версию, пример и инструкцию; для модулей — также
JavaScript MIME и CORS. Он не ждёт неизменённых ресурсов портфолио.
Публикация по-прежнему требует успешного Quality точного коммита и одного SHA
в `main` и `gh-pages`. Изменения самих проверок выбирают профиль `checks`:
контракты выбора, выполнения, публикационного барьера и сборки, затем сценарии
подписи. Это не разрешает менять рисунок или оформление потребителей.

## Общая публикация и обновления

1. Локально собрать и посмотреть затронутое состояние. Для этой упаковки —
   принятый 07 на 404 и пример без CSS портфолио, включая паузу и узкую ширину.
2. Повысить `VERSION` в `src/component.js`, собрать модуль и сохранить копию
   в `signature/<версия>/signature.js`. Обновить номер выпуска в этой инструкции
   и на странице примеров. Опубликовать точную версию вместе с каналом
   `signature/v1/`. Старые точные версии не перезаписывать.
3. Проверить публичный модуль: JavaScript MIME, CORS для загрузки с других
   доменов, реальный срок кэширования. Для `/v1/` нужен короткий срок или
   проверка актуальности; точные версии можно кэшировать надолго.
   На строгом CSP согласовать разрешение модуля и встроенного стиля с политикой
   принимающего сайта; Shadow DOM не является границей безопасности.
4. Только после успешной публикации подключать выбранные сайты к общему URL.
   Релиз компонента сам по себе не изменяет их HTML. Один раз подключённые
   сайты получат обновления канала при новых загрузках с учётом кэша.

В `/v1/` допустимы совместимые исправления, сохраняющие размер, параметры
и принятую композицию. Новая композиция или несовместимое поведение — отдельная
версия и отдельный выбор, без неожиданной переделки всех футеров.
Откат канала: вернуть сохранённую точную сборку; учитывать уже закэшированные ответы.
Проект, которому нужна фиксация, подключает точный номер вместо `/v1/`.
