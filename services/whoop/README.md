# WHOOP для личного сайта

Сервис работает в Cloudflare Workers и получает данные независимо от Mac и местного MCP.
Это отдельное приложение WHOOP с отдельным OAuth-подключением. Ключи MCP сюда не копируются.

- Публичная сводка: `https://portfolio-whoop.portfolio-whoop-service.workers.dev/day.json`.
- Описание обработки данных: `/privacy`.
- Расписание: минуты 7, 22, 37 и 52 каждого часа (UTC). Cloudflare может запустить обработчик с небольшой задержкой.
- Из WHOOP API v2 запрашиваются текущий цикл, связанное восстановление и основной сон.
  Записи сопоставляются по ID; сон исключает время бодрствования и отсутствия данных.
- Публикуются только восстановление, фактическая продолжительность сна, нагрузка и даты.
  HRV, пульс, ID пользователя, тренировки и ключи не публикуются и не сохраняются в сводке.
- SQLite Durable Object хранит один набор ключей и последнюю сводку. История не накапливается.
  Запросы обновления выполняются последовательно: новый refresh token сохраняется до запросов данных.
- При временной ошибке остаётся последняя датированная сводка. Через два часа без успешного
  получения данных или 36 часов после окончания сна сайт отключает зависимую палитру.
- Утреннее время расчёта восстановления не является признаком устаревания.
  Обновление нагрузки зависит от синхронизации браслета; `updated_at` — дата записи WHOOP,
  а не обещание непрерывного измерения.

## Развёртывание

Из этой папки: `npm ci`, `npm test`, `npx wrangler deploy --dry-run`, затем `npx wrangler deploy`.
Wrangler получает только `account:read`, `user:read`, `workers_scripts:write` и сохраняет
авторизацию с `--use-keyring`. Для работы DO и расписания не нужны Pages, DNS или R2.

В Cloudflare настроены три секрета: `ADMIN_TOKEN`, `WHOOP_CLIENT_ID`, `WHOOP_CLIENT_SECRET`.
Не помещать их значения в репозиторий, команды с видимыми аргументами, скриншоты или логи.
Права приложения WHOOP: `read:recovery`, `read:sleep`, `read:cycles`; OAuth также запрашивает `offline`.
Redirect URL должен точно совпадать с адресом сервиса и путём `/oauth/callback`.

Авторизованный POST `/connect` возвращает одноразовый URL WHOOP. Срок state — десять минут;
повторное использование callback отклоняется. POST `/refresh` запускает обновление вручную.
POST `/disconnect` удаляет ключи подключения, последний публичный снимок и ожидающий state.
Все три запроса требуют заголовок `Authorization: Bearer <ADMIN_TOKEN>`.
Локальная копия административного ключа находится в `~/.config/portfolio-whoop/admin-token`
с правами `0600`; она нужна для управления подключением, но не для работы расписания.

После отзыва доступа в WHOOP следующий запрос обновления удаляет недействительные ключи
и сводку. Для немедленного снятия данных использовать `/disconnect`.
Публичная сводка не кэшируется, CORS разрешает чтение с `https://gorokhovatsky.tech`.
Настройка CORS не делает данные закрытыми: три показателя предназначены для публичного сайта.

## Проверки

`npm test` проверяет состав публичной сводки, ID-связи, состояния расчёта,
недоступность административных действий для посетителей, одноразовый OAuth state,
сериализацию ротации ключей, временные сбои и отзыв доступа.
Проверки интерфейса находятся в `scripts/check-whoop-ui.mjs`; они используют тестовую
сводку и не обращаются к реальному аккаунту. Сам сайт читает URL из `meta[name="whoop-feed"]`.
