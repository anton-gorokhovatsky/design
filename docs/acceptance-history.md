## 4 сентября 2026 — платформенная клавиша в Linux WebKit

Исправление полосы `acc498b` опубликовано; Pages 33888811465 успешен,
21 runtime asset совпадает с commit. Полный локальный gate PASS (337,9 s).
Публичный scroll-контракт прошёл desktop light/dark, mobile light/dark и 320.
Кейс `eleven` проверен wheel до конца и обратно, его публичный нижний кадр
просмотрен. Исходный публичный flow один раз остановился на ожидании playback;
изолированный playback и исходный flow с записью событий медиа прошли.
Тест теперь сначала ждёт готовности всего кейса, переключает reduced motion
и проверяет реальный ход currentTime с бюджетом на публичную загрузку файла.
Первый локальный gate этой тестовой коррекции выявил неверное ожидание
декодированного кадра до включения движения: при preload=metadata WebKit
вправе загрузить только метаданные. Ожидание декодирования перенесено после
разрешения playback; само видео и его preload не изменены. До commit/push
тот проход был остановлен, затем запускается один исправленный полный повтор.

Quality 33888812032: Chromium, static и все четыре WebKit core — PASS;
WebKit case-view — 10/10 PASS, включая 200%, геометрию и скрытую полосу.
Последний flow остановился исключительно на Home после ArrowDown (строка 85).
Кадр Linux показывает сохранённый фокус области и небольшой сдвиг после ArrowDown.
В нативном `WebKit/UIProcess/gtk/KeyBindingTranslator.cpp` Home сопоставлен
`MoveToBeginningOfLine`, а Control+Home — `MoveToBeginningOfDocument`.
Linux WebKit-тест использует соответствующее платформе сочетание, остальные
движки сохраняют Home. Проверка достижения scrollTop=0 и неподвижного X сохранена;
между клавишами ожидается завершение прокрутки. Runtime, CSS и ресурсы неизменны.
Источник: https://github.com/WebKit/WebKit/blob/main/Source/WebKit/UIProcess/gtk/KeyBindingTranslator.cpp

Это отдельная установленная причина, а не слепой повтор прошлого CI.
Результат следующего полного gate и Quality фиксируется после исполнения;
в этой записи он не объявлен заранее.

## Архивный снимок исходной матрицы

Этот документ — небольшой статический workbench для vanilla HTML/CSS/JS-сайта.
Он фиксирует состояния, которые иначе остаются скрытыми в условных ветках
семи runtime-модулей `js/` и поздних слоях `styles.css`.

Storybook для проекта не нужен: компонентов немного, сборщика нет, а источник
истины — реальная полноэкранная композиция. Нужны воспроизводимые состояния и
рендеры, а не новый runtime.

## Принцип проверки

1. Сначала запустить `node scripts/audit-project.mjs`.
2. Выбрать из таблицы состояния, которых касается изменение.
3. Снять рендеры до и после в одинаковых viewport, theme и UI-state.
4. Проверить computed styles спорных элементов, а не делать вывод только по
   позиции декларации в `styles.css`.
5. Для каждого затронутого визуального семейства снять крупные кропы 1:1:
   общий экран фиксирует композицию, но не заменяет модульную приёмку.
6. На каждом кропе отдельно проверить колонки, baseline, оптические центры
   маркеров, разделители, длины строк, внутренний воздух и воспринимаемую
   однородность материала.
7. Для финального прохода выполнить всю матрицу.

Если дефект найден после заявления о готовности, приёмка всего связанного
семейства автоматически отзывается. Оно снова считается непроверенным, пока
не исправлены все его состояния и не снят новый комплект кропов.

Имена артефактов: `<viewport>-<theme>-<state>.png`, например
`1440x900-dark-project-reel.png`.

Chromium-проход в первой попытке прошли. После коррекции запускается один
полный повтор выпускного gate.

До повтора отдельно пройден контракт всех destination-ссылок. В нём также
обновлено старое ожидание Tab сразу после крестика: теперь проверяется точная
последовательность «область чтения → управление медиа на desktop → ссылка»,
а на mobile медиа следует ниже ссылки. Проверка реального открытия внешнего
адреса клавишей Enter сохранена; Option-Tab применяется только к macOS WebKit.

В Chromium отдельный замер первой mobile-карточки захватывал начальную
transform-матрицу даже при reduced motion (низ 846 px до layout commit против
832 px в завершённом состоянии при высоте 844 px). Контракт теперь ждёт
завершения собственных анимаций inspector, а не один произвольный RAF.
После этого все 49 карточек на desktop/mobile/reflow и десять представителей
на tablet/compact прошли в обеих темах; WebKit также прошёл весь набор.
